# V26 高收益回测与实盘差距

## 研究目标

本研究不先改入场条件，也不先把策略降成固定仓位。目标是解释高收益动态 V26 回测和实盘权益之间的差距，并建立一套可以重放、归因和验证的实盘仿真方法。

暂定目标策略为四组 2×2 中收益最高的**动态 + 恢复**：

- 回测区间：2026-01-01 至 2026-10-26 19:15 UTC；
- 起始资金：1,000 USDT；
- 历史结果：+1,503.49%、PF 1.30、账户最大回撤 38.11%；
- 对照策略：动态 + 无恢复；
- 风险基准：固定 + 恢复；
- 四组对照记录：[run-006](../v26-signal-separation/experiments/run-006-v26-2x2-1000/experiment.md)。

如果实际实盘对应的不是动态 + 恢复，而是另一个 V26 版本，必须在实验开始前替换目标版本，不能混用交易记录。

## 要回答的核心问题

1. 回测和实盘是否真的执行了同一组信号？
2. 差距有多少来自信号路径、成交执行、费用／资金费、数据时间和仓位反馈？
3. 这些差距是随机噪声，还是在某些币、时段、信号分支和市场状态下重复出现？
4. 在保留动态复利的前提下，哪一种最小修正能提高实盘几何增长率，而不是只提高历史终值？
5. 修正是否能在未参与调参的 forward 区间成立？

## 数学定义

逐笔复利权益定义为：

```text
E_(i+1) = E_i * (1 + f_i * r_i)
```

其中 `f_i` 是实际资金暴露，`r_i` 是扣除交易成本后的单笔收益率。比较对象使用对数权益差：

```text
gap_T = log(E_backtest_T) - log(E_live_T)
```

执行层的初始分解为：

```text
r_live = r_signal
          - fee
          - slippage
          - funding
          - latency_loss
          - missed_or_rejected_loss
          + replacement_trade_effect
```

不能把未成交信号直接当作亏损交易删除。过滤或延迟会改变唯一持仓位的占用、后续信号和动态仓位，因此必须使用事件驱动的反事实重放。

## 研究框架

### A. 版本和数据对齐

目标：排除“比较的不是同一个策略”这种最基础的错误。

- 固定策略文件哈希、参数 JSON、交易池、时间区间、时区、杠杆和费用；
- 核对回测和实盘的 K 线来源、闭合时间、缺失 K 线和交易对上市时间；
- 统一外部充提、起始权益、未平仓仓位和账户余额口径；
- 为每个信号保存策略版本、数据时间戳和决策时刻。

产物：版本对齐表、数据缺失表、可配对的信号清单。

### B. 逐笔配对和差距账本

目标：把“差很多”变成每一笔可核对的数字。

每条记录至少包含：

- 回测信号时间和实盘信号时间；
- 交易对、方向、`enter_tag`、退出原因；
- 理论入场价、实际委托价、实际成交价、数量；
- 委托到成交的延迟、部分成交、撤单和拒单；
- 手续费、资金费、滑点和实际持仓时间；
- 回测收益、实盘收益和两者差值；
- 当时账户余额、峰值余额、实际仓位和杠杆。

产物：`gap-ledger.csv`、逐笔配对报告、未配对信号清单。

### C. 反事实执行重放

目标：区分信号问题和成交问题。

对同一组信号构造四条路径：

1. 理想回测成交；
2. 实盘信号 + 理想成交；
3. 实盘信号 + 实际成交成本；
4. 实际账户结果。

四条路径之间的差值分别对应信号／数据差异、执行成本和账户运行差异。

产物：P&L waterfall、每个差距来源的金额和比例、按币种／分支／时段的归因。

### D. 分布漂移与结构变化

目标：判断实盘是否进入了回测中没有覆盖的状态。

比较入场前可见变量：

- BTC 和币自身的 1h、4h、24h 收益；
- 波动率、价差、成交量和盘口深度；
- 信号年龄、同一时刻信号数量；
- 下单延迟、成交偏离和资金费。

使用 PSI、Wasserstein distance、MMD、条件收益分布和 CUSUM／变点检测。不能只比较“涨、跌、震荡”标签。

产物：回测／实盘状态分布报告、漂移时间点、风险状态标签。

### E. 稳健性与过拟合约束

目标：避免为了追上某一段实盘曲线而把历史噪声调进策略。

- Purged Walk-Forward；
- Embargo 防止相邻持仓泄漏；
- Nested validation；
- Block Bootstrap 保留时间相关性；
- White Reality Check 或 SPA 检验多重尝试；
- Deflated Sharpe Ratio 和 Probability of Backtest Overfitting；
- 所有阈值、仓位映射和通过标准先登记。

产物：独立训练／验证／forward 结果、置信区间和尝试次数清单。

### F. 复利和仓位修正

目标：在不直接放弃高收益的情况下，控制实盘误差被滚仓放大的程度。

候选方法按风险从低到高排列：

1. 保留动态滚仓，但使用实际成交后的权益更新；
2. Fractional Kelly，而不是满额动态仓位；
3. 基于实时估计的风险预算和 CVaR 限制；
4. 只在成交质量恶化时降低暴露，不按收益结果事后调仓；
5. 将最大仓位、单日损失和连续亏损熔断作为外部约束。

目标函数不使用单一终值，而采用：

```text
J(theta) = E[log(1 + return(theta))]
           - lambda * CVaR(drawdown(theta))
           - mu * unexplained_gap(theta)
```

产物：候选仓位函数、实盘仿真结果和参数敏感性表。

### G. Forward 验证与监控

目标：确认修正不是只对旧数据有效。

- 先记录，不直接下单；
- 同时运行目标策略、对照策略和风险基准；
- 记录实际滑点、资金费、成交延迟、未平仓权益和信号簇；
- 使用滚动 PF、几何增长率、回撤、CVaR 和 CUSUM 监控；
- 只有通过预先登记的 forward 标准，才讨论小额灰度。

产物：forward 周期报告、漂移警报、上线／停止决定。

## 预先登记的判断规则

- 不能用最终收益率单独判断成功；必须同时报告几何增长率、PF、最大回撤、CVaR、连续亏损和未解释差距；
- 不能把被过滤信号直接删除来计算“改进后收益”；必须重放释放持仓位后的替代交易；
- 不能把已参与选参的区间称为独立验证；
- 不能用实盘一小段盈利证明长期有效，也不能用单个异常交易证明策略必然失效；
- 没有完整订单和账户权益数据时，结论只能是“无法归因”，不能猜测原因。

## 目前缺少的数据

仓库已有 V26 四组回测和策略参数，但没有完整的实盘订单级账本。因此目前只完成研究设计，尚未完成差距归因。后续需要从服务器或交易所导出：订单、成交、手续费、资金费、账户权益、未平仓记录、策略日志和对应 K 线快照。读取和复制数据时必须脱敏，不把密钥、真实配置或账户资料写入公开研究代码。

## 当前决定

先不改实盘策略，不把固定仓位版本当作最终收益方案，也不继续盲目调 BTC 环境阈值。先完成 run-001 和 run-002；如果无法取得可配对的实盘订单数据，研究停止在“无法归因”，不编造实盘结论。
