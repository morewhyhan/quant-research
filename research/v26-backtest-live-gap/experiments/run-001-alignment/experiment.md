## 这次要查什么？

确认“高收益动态 V26 回测”和实际实盘是否真的是同一个可比较对象。只做审计，不改策略、不重调参数、不连接生产账户。

重点核对：

1. 策略文件及其父类的 Git 哈希；
2. 参数 JSON、配置文件、杠杆、保证金模式和最大持仓数；
3. 交易所、合约类型、交易对列表和交易对有效时间；
4. K 线时间戳、时区、闭合规则、缺失 K 线和数据结束时间；
5. 回测起始权益、实盘起始权益、外部充提和未平仓仓位；
6. 费用、资金费、滑点和成交价格的实际口径；
7. `loss_half_recovery`、动态仓位函数和信号门控是否为同一版本。

## 怎样运行？得到什么？

计划生成：

- `alignment-manifest.json`：文件哈希、参数和数据版本；
- `data-coverage.md`：每个交易对的起止时间、缺失区间和时区；
- `comparison-contract.md`：明确后续实验允许比较的共同口径；
- `missing-live-fields.md`：实盘缺失字段和无法归因的影响。

计算口径：所有金额同时保留 USDT 和收益率；收益使用已实现收益时注明不含未平仓权益；外部充提单独列出，不混入策略收益。

预计耗时：数据可读时为一次审计；若实盘日志缺失，停止在缺失清单，不猜测原因。

## 停止条件

- 策略版本或参数无法确定：停止比较终值；
- 实盘没有订单和成交时间：只能做粗粒度账户曲线对比，不能做逐笔归因；
- 时间区间或交易池不一致且无法重建：新建独立研究，不强行合并。
