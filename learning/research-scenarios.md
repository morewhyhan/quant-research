# 按问题选方法

同一个项目可以先检验因子，再比较策略和仓位，不必复制项目。记录方式见[使用说明](../仓库使用说明.md)，现有功能见[工具说明](../tools/README.md)。

研究完整交易策略时，可选择参考[严格策略开发 SOP 的完整中译](strategy-validation.md)；它不是本仓库的默认强制流程。

## 要研究什么？

| 问题 / 命令中的类型 | 怎样做 | 保存什么 |
| --- | --- | --- |
| 规则为什么这样算 mechanism | 拆公式、手算、找反例、核对代码 | 推导、例子和适用条件 |
| 指标能否预测涨跌 factor | 明确当时知道的信息，比较信号后固定时间的收益 | 预测结果、分组和不同时间段表现 |
| 策略能否赚钱 strategy | 固定基准，模拟交易、仓位和费用 | 账户曲线、交易、成本和风险 |
| 能否复现别人的策略 replication | 先还原原规则，再单独改版 | 来源、实现差别和两者结果 |
| 参数怎样选 optimization | 先定候选范围，再分开训练、选参和最终测试 | 全部尝试、选择理由和独立测试 |
| 仓位或组合怎样配 portfolio | 算共享资金、同向持仓、调仓和费用 | 账户收益、风险来自哪里、是否一起亏 |
| 数据能否用 data | 查覆盖、时区、重复、修订和发布时间 | 缺失清单、字段解释和适用范围 |
| 能否按预期成交 execution | 对照信号、下单、确认、成交和撤单 | 各步时间、滑点和可成交数量 |
| 实盘为什么不同 live | 先统一版本、配置、持仓和时区，再逐笔查日志 | 对得上的交易、差异和原因 |
| 换条件还行不行 robustness | 换时期、提高成本、查不利情况，必要时重复抽样 | 结果怎样变化、哪些结论还成立 |

不涉及交易就不填 PF，不适用也不填零。选择一种类型只会调整记录提示，不会自动实现对应模型。

## 遇到问题怎么办？

| 情况 | 做法 |
| --- | --- |
| 拿不到数据 | 先回答能回答的部分，写清还缺什么、何时能继续 |
| 数据缺字段但仍可算 | 保留实际假设与结果；缺失使实验无法回答原问题时，才判无效 |
| 运行中断 | 留下命令、日志、进度和中断位置；恢复或重跑时链接原实验 |
| 程序或参数出错 | 保留错误运行，说明影响，修正后新建实验 |
| 结果与预想相反 | 先查比较条件；结果没错就改变判断 |
| 不断选参 | 记下候选范围和尝试次数，不只贴最好的结果 |
| 换市场或产品 | 先补产品规则、数据、费用和成交方式，再改策略 |
| 多人或多个 AI | 分开实验目录，共享文件商量后合并 |
| 批量搜索参数 | 同一实验保存配置、随机种子和每组结果，不为每组建研究项目 |
| 暂停或停止 | 写清已知结果、停止原因和继续所需材料，保留证据 |
| 不能公开材料 | 说明来源和获取条件，敏感原文留在私有区 |

## 怎样判断？

先选主要指标，写下什么结果值得继续、什么结果该停止。历史记录后补的解释，不写成当时就有的计划。

“算出了什么”“为什么这样”“以后是否仍然如此”分开回答。缺哪个答案，就具体写哪个。

不要提前用未来信息。例如，计算信号、选币或选参数时，只用当时可知的数据。训练和测试按时间分开后，还要检查是否共享未来标签：如果标签是未来几天的收益，它可能跨过分界线。TimeSeriesSplit 能帮助按时间划分，但不能自动排除所有泄漏。[官方说明](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.TimeSeriesSplit.html)

反复筛选会增加“碰巧挑中好结果”的可能。需要时可用 PBO 等方法研究这个问题，不必每项都套用。[原论文](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)

同一天的多个币或相邻交易可能受同一行情影响。估计误差范围时，要说明抽样单位和算法，不能把这些记录都当成互不相关。

调查实盘差异要查订单和日志，研究仓位要看账户变化，复现期权策略要有对应历史报价。资料或工具缺什么，就先写清，不用一张收益表代替。
